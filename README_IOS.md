# Запуск iOS-автотестов на реальных устройствах
Инструкция предназначена для тестировщиков, которые раньше не работали с Java, Maven, Appium и Xcode.

iOS-автотесты запускаются только на Mac и только на реальных iPhone. Можно использовать один или несколько одновременно подключённых устройств.

## Важно перед началом настройки
Appium управляет iPhone через служебное приложение `WebDriverAgent`, сокращённо `WDA`.

При первом запуске WDA:
1. собирается в Xcode;
2. подписывается сертификатами Apple Developer Team;
3. устанавливается на iPhone;
4. запускается на устройстве;
5. передаёт команды от Appium приложению FitnessOnline.

Для запуска тестов iPhone должен быть зарегистрирован в Apple Developer Team, а WebDriverAgent должен быть подписан и хотя бы один раз успешно запущен через Xcode.
Новое устройство может получить состояние `Processing`. Пока Apple не завершит обработку, WebDriverAgent может не собираться или не устанавливаться.

> [!WARNING]
> **Обработка нового iPhone может занять до 72 часов, поэтому первичную настройку устройства необходимо выполнять заранее.**

## 1. Что нужно установить
На Mac должны быть установлены:
1. Git: https://git-scm.com/downloads
2. IntelliJ IDEA: https://www.jetbrains.com/idea/download/
3. Java JDK 17: https://adoptium.net/
4. Node.js 24: https://nodejs.org/
5. Xcode из App Store
6. Appium 3.5.2
7. iOS-драйвер Appium XCUITest 11.17.4
Appium и драйвер XCUITest будут установлены позже по этой инструкции.

Также понадобятся:
- один или несколько реальных iPhone;
- USB-кабель для каждого устройства;
- установленное приложение FitnessOnline;
- доступ к приватному репозиторию GitHub;
- доступ к Apple Developer Team `FITNESS ONLINE MChJ`.

Отдельно устанавливать Maven, npm, `xcrun` и `xctrace` не нужно:
- Maven проект скачает автоматически;
- npm устанавливается вместе с Node.js;
- `xcrun` и `xctrace` устанавливаются вместе с Xcode.

## 2. Получение доступа к проекту
Репозиторий приватный. Без приглашения открыть или скачать его нельзя.

### Что должен сделать владелец проекта
1. Узнать имя пользователя тестировщика на GitHub.
2. Открыть репозиторий.
3. Перейти в `Settings` → `Collaborators`.
4. Нажать `Add people`.
5. Найти тестировщика по имени пользователя.
6. Отправить приглашение.

### Что должен сделать тестировщик
1. Открыть письмо или уведомление от GitHub.
2. Принять приглашение.
3. После этого репозиторий станет доступен его аккаунту.

## 3. Получение доступа к Apple Developer Team
Для подписи WebDriverAgent нужен Apple Account, добавленный в команду `FITNESS ONLINE MChJ`.

Это не обязательно должен быть аккаунт, который используется для входа на Mac или на самом iPhone. Нужно использовать именно тот Apple Account, на который было отправлено приглашение в Apple Developer Team.

### Добавление аккаунта в Xcode
1. Откройте Xcode.
2. Примите лицензионное соглашение, если Xcode показывает такой запрос.
3. Дождитесь установки дополнительных компонентов.
4. В верхнем меню выберите `Xcode` → `Settings`.
5. Откройте раздел `Apple Accounts`.
6. Нажмите кнопку `+`.
7. Добавьте рабочий Apple Account.
8. Выберите команду `FITNESS ONLINE MChJ`.

В информации о команде должно отображаться:
```text
Role
Developer
```

Возле строки:
```text
Certificates, Identifiers, & Profiles
```
должна стоять зелёная галка.

Если команда отсутствует, указана другая роль или нет зелёной галки, обратитесь к администратору или владельцу Apple Developer Team. Самостоятельно менять `TEAM_ID` в проекте не нужно.

## 4. Установка Appium
Откройте системное приложение `Терминал`:
1. Нажмите `Command + Space`.
2. Введите `Terminal`.
3. Откройте найденное приложение.

Установите Appium:
```bash
npm install --global appium@3.5.2
```

Установите iOS-драйвер XCUITest:
```bash
appium driver install xcuitest@11.17.4
```

Проверьте установку:
```bash
appium driver doctor xcuitest
```

Если в результате указано:
```text
0 required fixes needed
```
обязательные компоненты установлены.

После установки полностью перезапустите IntelliJ IDEA.

## 5. Загрузка проекта
1. Откройте IntelliJ IDEA.
2. На стартовом экране нажмите `Get from VCS` или `Clone Repository`.
3. Вставьте адрес:
```text
https://github.com/deno-fo/FitnessOnlineAutoQA.git
```
4. Нажмите `Clone`.
5. Если IDEA попросит войти в GitHub, войдите под аккаунтом, которому выдали доступ.
6. Разрешите IntelliJ IDEA доступ к GitHub.
7. Откройте загруженный проект.
8. Дождитесь завершения загрузки Maven-зависимостей.

При первой загрузке это может занять несколько минут.

## 6. Где вводить команды
Команды запуска тестов нужно вводить в терминале внутри IntelliJ IDEA.

Чтобы открыть его:
1. В верхнем меню IDEA нажмите `View`.
2. Выберите `Tool Windows`.
3. Нажмите `Terminal`.

Перед вводом команды убедитесь, что слева от курсора присутствует название проекта:
```text
FitnessOnlineAutoQA
```

Пример:
```text
admin@MacBook FitnessOnlineAutoQA %
```

Если названия проекта нет, терминал открыт не в папке проекта. Закройте его и откройте заново через IntelliJ IDEA.
Команды первичной настройки Xcode и WebDriverAgent можно выполнять в системном Терминале.

## 7. Настройки Apple Developer Team в проекте
Настройки команды находятся в файле:
```text
src/test/java/utils/IosConfig.java
```

В нём указаны:
```text
TEAM_ID
WDA_BUNDLE_ID
```

Обычному тестировщику самостоятельно искать, придумывать или изменять эти значения не нужно.
Значение `WDA_BUNDLE_ID` в этом файле является исходным значением для Bundle Identifier в Xcode.

Настройки меняются только в следующих случаях:
- проект переносится в другую Apple Developer Team;
- владелец проекта сообщил новые значения;
- изменился Bundle ID WebDriverAgent.

Если Xcode не показывает команду `FITNESS ONLINE MChJ`, необходимо получить доступ к правильной Apple Developer Team, а не менять `TEAM_ID` в коде.

## 8. Подключение и проверка iPhone
На каждом iPhone необходимо:
1. Подключить устройство к Mac кабелем.
2. Разблокировать экран.
3. Подтвердить доверие к компьютеру.
4. Открыть `Настройки` → `Конфиденциальность и безопасность`.
5. Включить `Режим разработчика`.
6. Перезапустить iPhone, если система попросит это сделать.
7. После перезапуска подтвердить включение режима разработчика.
8. Открыть `Настройки` → `Разработчик`.
9. Включить `Enable UI Automation`.

Проверьте подключение в системном Терминале:
```bash
xcrun xctrace list devices
```

В разделе:
```text
== Devices ==
```
должны отображаться все подключённые iPhone.

Пример:
```text
Admin's iPhone (26.5) (00008140-000202E136D2801C)
```

В этой строке:
- `Admin's iPhone` — имя устройства;
- последняя строка в скобках — UDID устройства.

Имя и UDID вручную в коде указывать не нужно. Они могут понадобиться для проверки регистрации iPhone в Apple Developer Team или запуска теста только на выбранном устройстве.

## 9. Первичная настройка WebDriverAgent
Настройка выполняется на новом Mac, после полной переустановки iOS-драйвера Appium или для нового iPhone.

Подключите и разблокируйте iPhone, затем выполните в системном Терминале:
```bash
appium driver run xcuitest open-wda
```
Проект WebDriverAgent откроется в Xcode.

### Настройка подписи
1. В левой панели выберите проект `WebDriverAgent`.
2. В разделе `Targets` выберите `WebDriverAgentRunner`.
3. Убедитесь, что выбран нужный iPhone.
4. Откройте `Signing & Capabilities`.
5. Включите `Automatically manage signing`.
6. В поле `Team` выберите:
```text
FITNESS ONLINE MChJ
```

7. Если Xcode сообщает, что устройство не зарегистрировано, нажмите `Register Device`.
Не закрывайте вкладку `Signing & Capabilities`. Перед запуском WebDriverAgent необходимо проверить Bundle Identifier.

### Проверка Bundle Identifier
В той же вкладке `Signing & Capabilities` найдите поле `Bundle Identifier`.

Затем откройте в проекте файл:
```text
src/test/java/utils/IosConfig.java
```
Сравните значение в поле `Bundle Identifier` в Xcode со значением `WDA_BUNDLE_ID` из файла `IosConfig.java`.

Если значения не совпадают, замените Bundle Identifier в Xcode на значение `WDA_BUNDLE_ID` из проекта.
Самостоятельно придумывать новый идентификатор не нужно.

> [!NOTE]
> У установленного на iPhone тестового приложения к Bundle Identifier может автоматически добавляться суффикс `.xctrunner`.
> Вручную добавлять этот суффикс в поле `Bundle Identifier` не нужно.

### Запуск WebDriverAgent
1. Откройте `Product` → `Scheme`.
2. Выберите `WebDriverAgentRunner`.
3. Откройте `Product` → `Destination`.
4. Выберите нужный iPhone.
5. Нажмите `Product` → `Test`.

Если WebDriverAgent успешно установился и запустился, первичная настройка завершена.
Для каждого iPhone, который будет участвовать в параллельном запуске, WebDriverAgent должен быть заранее подготовлен таким же способом.

## 10. Проверка регистрации iPhone
После попытки запуска WebDriverAgent проверьте устройство в [списке устройств Apple Developer](https://developer.apple.com/account/resources/devices/list).

Пошагово:
1. Откройте Apple Developer.
2. Нажмите `Account`.
3. Войдите в рабочий Apple Account.
4. Выберите команду `FITNESS ONLINE MChJ`.
5. Откройте `Certificates, Identifiers & Profiles`.
6. Откройте раздел `Devices`.
7. Найдите iPhone по имени или UDID.

Возможны три состояния:
- устройство активно (поле `Status` пустое);
- устройство находится в состоянии `Processing`;
- устройство отсутствует в списке.

### Если устройство активно (поле `Status` пустое)
Дополнительное ожидание не требуется. Можно переходить к запуску тестов.

### Если устройство находится в состоянии `Processing`
Дождитесь завершения обработки. Она может занять до 72 часов.

Пока состояние `Processing` не исчезло:
- WebDriverAgent может не устанавливаться;
- повторно добавлять устройство не нужно;
- менять настройки проекта не нужно.

После завершения обработки снова запустите WebDriverAgent через Xcode.

### Если устройство отсутствует в списке
Сначала повторите настройку WebDriverAgent:
1. Убедитесь, что включено `Automatically manage signing`.
2. Убедитесь, что выбрана команда `FITNESS ONLINE MChJ`.
3. Убедитесь, что выбран нужный iPhone.
4. Повторно нажмите `Register Device`.

Если устройство всё равно не появилось, передайте администратору или владельцу команды:
- имя iPhone;
- UDID iPhone.

Администратор должен добавить устройство вручную через раздел `Devices` на сайте Apple Developer.
После регистрации необходимо дождаться, пока устройство станет активным, а затем снова запустить WebDriverAgent через Xcode.

1. В верхнем меню IDEA откройте `Git`.
2. Нажмите `Pull`.
3. Дождитесь завершения обновления.

## 12. Подготовка iPhone перед тестом
Перед каждым запуском убедитесь, что каждый iPhone:
1. подключён к Mac;
2. разблокирован;
3. доверяет Mac;
4. имеет включённый `Режим разработчика`;
5. имеет включённый `Enable UI Automation`;
6. отображается в выводе `xcrun xctrace list devices`;
7. имеет установленное приложение FitnessOnline;
8. использует английский язык приложения;
9. заранее подготовлен для запуска WebDriverAgent.

К Mac можно одновременно подключить один или несколько iPhone.

## 13. Запуск Appium
В терминале IntelliJ IDEA выполните:
```bash
appium
```

Не закрывайте эту вкладку. Appium должен работать всё время, пока выполняются тесты.
Для запуска тестов откройте вторую вкладку терминала кнопкой `+`.

Одного сервера Appium достаточно для всех подключённых iPhone.

## 14. Запуск всех iOS-тестов
Во второй вкладке терминала IntelliJ IDEA выполните:
```bash
./mvnw test -Pios
```

Все iOS-тесты будут запущены на всех подключённых iPhone.
На каждом устройстве тесты выполняются по очереди, а разные устройства работают параллельно.

Во время выполнения:
- не отключайте кабели;
- не блокируйте iPhone;
- не закрывайте Appium;
- не управляйте приложением вручную.

## 15. Запуск тестов через IntelliJ IDEA
Отдельный тест или весь тестовый класс можно запустить без Maven-команды.
Перед запуском должны быть подключены и разблокированы iPhone, а Appium должен работать.

1. В левой части IDEA откройте:
```text
src → test → java → tests → ios
```
2. Найдите нужный тест. Названия iOS-тестов начинаются со слова `Ios`, например:
```text
IosGuestAccountCreationTest
```
3. Откройте файл двойным щелчком.
4. Нажмите зелёный треугольник рядом с названием класса, чтобы запустить весь класс.
5. Либо нажмите зелёный треугольник рядом с отдельным тестовым методом.
6. Выберите `Run`.

Фреймворк автоматически запустит выбранный тест на всех подключённых iPhone.

Результат появится во вкладке `Run`.
Файл `BaseIosTest` запускать не нужно. Это базовый класс с общими настройками.

## 16. Запуск одного теста командой
Например, для запуска `IosGuestAccountCreationTest`:
```bash
./mvnw test -Pios -Dtest=IosGuestAccountCreationTest
```

Если подключено несколько iPhone, тест будет запущен на каждом из них.

Чтобы выполнить его только на одном устройстве, передайте UDID:
```bash
./mvnw test -Pios \
  -Dtest=IosGuestAccountCreationTest \
  -Dios.udid=00008140-000202E136D2801C
```

В примере:
- `IosGuestAccountCreationTest` — название тестового класса;
- `00008140-000202E136D2801C` — UDID выбранного iPhone.

Команда вводится во второй вкладке терминала IntelliJ IDEA.

## 17. Одновременный запуск Android- и iOS-тестов
Android- и iOS-тесты можно выполнять одновременно через один сервер Appium:
1. Запустите Appium.
2. Запустите нужный Android-тест зелёной стрелкой в IntelliJ IDEA.
3. Не дожидаясь его завершения, запустите нужный iOS-тест другой зелёной стрелкой.

Тесты откроются в отдельных вкладках `Run` и будут выполняться одновременно.

## 18. Состояние системных разрешений
iOS не позволяет Appium полностью сбрасывать системные разрешения приложения между тестами.

Это относится, например, к:
- Apple Health;
- уведомлениям;
- другим системным запросам доступа.

После первого разрешения или отказа системное окно может больше не появляться. Поэтому поведение теста зависит от текущего состояния разрешений на устройстве.

Для повторной проверки первого системного запроса может потребоваться:
1. удалить FitnessOnline с iPhone;
2. установить приложение заново;
3. снова запустить тест.

## 19. Результат запуска

Очистка после сбоя сначала пытается восстановить доступ к `More`: закрывает подсказки,
отменяет открытые диалоги, закрывает отчёт и продолжает распознанные экраны онбординга.
Если нужный экран не найден, выполняется один перезапуск приложения с сохранением сессии.
Восстановление ограничено ожиданием; неизвестный или недоступный экран остаётся ошибкой очистки.

Удаление разрешается только для сценариев, которые начали создание тестового аккаунта
с экрана авторизации. Постоянный аккаунт в тесте входа только разлогинивается, в том числе
при падении после отправки данных входа, до финальной проверки главного экрана.

Локальные проверки восстановления (без айфона) запускаются отдельно и не входят в семь
мобильных iOS-кейсов:

```bash
./mvnw -Dskip.mobile.tests=false -Dtest=CleanupRecoveryTest,DeviceQuarantineTest test
```

После очистки каждый тест дополнительно проверяет, что приложение вернулось на экран
авторизации или приветствия без открытого системного alert. Если это не подтверждено,
тест завершается с ошибкой очистки. При наличии исходной ошибки сценария она сохраняется
основной, а ошибка очистки добавляется к ней.

Оставшиеся тесты на этом iPhone получают статус SKIP с указанием теста, после которого
состояние не восстановилось. Другие iPhone продолжают работу. Это ограничение действует
только внутри текущего запуска JUnit, а не между отдельными процессами.
Перед новым запуском вручную удалите оставшийся тестовый аккаунт или выйдите из него
и убедитесь, что открыт экран авторизации.

При запуске командой результат появится в терминале IntelliJ IDEA.
При запуске зелёной стрелкой результат появится во вкладке `Run`.

Успешный запуск выглядит примерно так:
```text
Failures: 0, Errors: 0
BUILD SUCCESS
```

Если `Failures` или `Errors` больше нуля, один или несколько тестов завершились с ошибкой.
Первый запуск может выполняться дольше, потому что Appium собирает, подписывает и устанавливает WebDriverAgent.

## 20. Частые проблемы

### Команда `xcrun xctrace list devices` не показывает iPhone
Проверьте:
- подключён ли iPhone к Mac;
- разблокирован ли экран;
- подтверждено ли доверие к компьютеру;
- включён ли режим разработчика;
- отображается ли iPhone в Xcode;
- исправен ли кабель.

### iPhone отображается в Xcode, но Appium не запускает новую сессию
Характерные признаки:
- iPhone отображается в Xcode;
- команда `xcrun xctrace list devices` видит устройство;
- Appium или Appium Inspector не могут создать новую сессию;
- на экране iPhone не появляется запрос кода-пароля для запуска автоматизации.

Сначала полностью перезагрузите iPhone.

Если проблема осталась:
1. закройте Appium Inspector;
2. остановите Appium;
3. выполните в Терминале:
```bash
pkill -f xcodebuild
pkill -f iproxy
```
4. снова запустите Appium:
```bash
appium
```
5. повторите запуск теста или создание сессии в Appium Inspector.

### Команда `./mvnw` не найдена
Команда введена не в папке проекта.

Откройте терминал через IntelliJ IDEA и убедитесь, что в его строке присутствует:
```text
FitnessOnlineAutoQA
```

### Команда `appium` не найдена
Appium не установлен или IntelliJ IDEA не была перезапущена после установки.

Выполните:
```bash
npm install --global appium@3.5.2
```
После этого полностью перезапустите IntelliJ IDEA.

### Команда `npm` не найдена
Node.js не установлен.
Установите Node.js 24 и заново откройте Терминал.

### Команда `xcrun` не найдена
Xcode не установлен или первоначальная настройка Xcode не завершена.
Откройте Xcode, примите лицензионное соглашение и дождитесь установки дополнительных компонентов.

### В Xcode нет команды `FITNESS ONLINE MChJ`
Проверьте:
- добавлен ли правильный Apple Account;
- принято ли приглашение в Apple Developer Team;
- отправлено ли приглашение на правильную электронную почту.

Если команда отсутствует, обратитесь к администратору или владельцу Apple Developer Team.

### Возле `Certificates, Identifiers, & Profiles` нет зелёной галки
Для аккаунта не выдан нужный доступ.
Обратитесь к администратору или владельцу Apple Developer Team. Менять `TEAM_ID` в коде не нужно.

### Устройство находится в состоянии `Processing`
Дождитесь завершения обработки Apple. Она может занять до 72 часов.
Пока устройство находится в состоянии `Processing`, WebDriverAgent может не устанавливаться.

### Устройство отсутствует в списке Apple Developer
Повторите первичную настройку WebDriverAgent с включённым `Automatically manage signing`.
Если автоматическая регистрация не произошла, передайте имя и UDID устройства администратору или владельцу команды.

### Ошибка подписи WebDriverAgent
Откройте проект WebDriverAgent:
```bash
appium driver run xcuitest open-wda
```

Проверьте:
- выбран ли `WebDriverAgentRunner`;
- включено ли `Automatically manage signing`;
- выбрана ли команда `FITNESS ONLINE MChJ`;
- Bundle Identifier в Xcode совпадает со значением `WDA_BUNDLE_ID` в `IosConfig.java`;
- возле `Certificates, Identifiers, & Profiles` есть зелёная галка;
- iPhone зарегистрирован в Apple Developer Team;
- состояние устройства не равно `Processing`;
- Xcode не показывает красную ошибку подписи.

Если ошибка остаётся, передайте владельцу проекта точный текст ошибки Xcode.

### Один из подключённых iPhone не участвует в параллельном запуске
Выполните:
```bash
xcrun xctrace list devices
```

Убедитесь, что проблемный iPhone:
- отображается в разделе `== Devices ==`;
- разблокирован;
- доверяет подключённому Mac;
- имеет включённые `Режим разработчика` и `Enable UI Automation`;
- зарегистрирован в Apple Developer Team;
- успешно запускает WebDriverAgent через Xcode.

Также убедитесь, что для каждого iPhone используется отдельный USB-кабель и соединение не прерывается во время тестов.

### Appium уже запущен
Не запускайте второй сервер. Используйте уже открытую вкладку Appium.
Одного сервера достаточно для всех подключённых устройств.

### Первый запуск выполняется долго
При первом запуске Appium собирает и устанавливает WebDriverAgent.
Последующие запуски обычно выполняются быстрее.
