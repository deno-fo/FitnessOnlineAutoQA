# Запуск Android-автотестов на реальном устройстве

Инструкция предназначена для тестировщиков, которые раньше не работали с Java, Maven и Appium.

## 1. Что нужно установить
На компьютере должны быть установлены:
1. Git: https://git-scm.com/downloads
2. IntelliJ IDEA: https://www.jetbrains.com/idea/download/
3. Java JDK 17: https://adoptium.net/
4. Node.js 24: https://nodejs.org/
5. Android Studio: https://developer.android.com/studio
6. Appium 3.5.2.
7. Android-драйвер Appium UiAutomator2 8.1.0.

Также понадобятся:
- один или несколько реальных Android-телефонов;
- USB-кабель;
- установленное приложение FitnessOnline;
- доступ к приватному репозиторию GitHub;
- интернет при первой загрузке проекта.

Отдельно устанавливать Maven, npm и ADB не нужно:
- Maven проект скачает автоматически;
- npm устанавливается вместе с Node.js;
- ADB устанавливается вместе с Android SDK Platform-Tools.

## 2. Получение доступа к проекту
Репозиторий приватный. Без приглашения открыть или скачать его нельзя.

### Что должен сделать владелец проекта
1. Узнать имя пользователя тестировщика на GitHub.
2. Открыть репозиторий.
3. Перейти в `Settings` → `Collaborators`.
4. Нажать `Add people`.
5. Найти тестировщика по имени пользователя.
6. Отправить приглашение.

### Что должен сделать тестировщик
1. Открыть письмо или уведомление от GitHub.
2. Принять приглашение.
3. После этого репозиторий станет доступен его аккаунту.

## 3. Установка Android SDK
1. Откройте Android Studio.
2. Откройте `Settings`.
3. Перейдите в `Languages & Frameworks` → `Android SDK`.
4. Установите любую актуальную версию `Android SDK Platform`.
5. Откройте вкладку `SDK Tools`.
6. Установите `Android SDK Platform-Tools`.

В верхней части окна будет указан путь к Android SDK.

На Mac стандартный путь выглядит так:
```text
/Users/имя-пользователя/Library/Android/sdk
```

На Windows:
```text
C:\Users\имя-пользователя\AppData\Local\Android\Sdk
```

## 4. Настройка Android SDK на Mac
Откройте системное приложение `Терминал`:
1. Нажмите `Command + Space`.
2. Напишите `Terminal`.
3. Откройте найденное приложение.

Введите по очереди:
```bash
echo 'export ANDROID_HOME="$HOME/Library/Android/sdk"' >> ~/.zshrc
echo 'export PATH="$ANDROID_HOME/platform-tools:$PATH"' >> ~/.zshrc
echo 'export JAVA_HOME=$(/usr/libexec/java_home -v 17)' >> ~/.zshrc
source ~/.zshrc
```

Проверьте ADB:
```bash
adb version
```

Если появилась информация о версии Android Debug Bridge, настройка выполнена.
Если команда не найдена, полностью закройте и заново откройте системный Терминал.

## 5. Настройка Android SDK на Windows
1. Откройте поиск Windows.
2. Найдите `Изменение системных переменных среды`.
3. Нажмите `Переменные среды`.
4. Создайте переменную `ANDROID_HOME`.
5. Укажите в ней путь к Android SDK, например:
```text
C:\Users\имя-пользователя\AppData\Local\Android\Sdk
```
6. Найдите переменную `Path`.
7. Добавьте в неё:
```text
%ANDROID_HOME%\platform-tools
```
8. Создайте переменную `JAVA_HOME`.
9. Укажите путь к установленному JDK 17.
10. Добавьте в `Path`:
```text
%JAVA_HOME%\bin
```
11. Сохраните изменения.
12. Перезапустите компьютер.

После перезапуска откройте приложение `Командная строка` и выполните:
```text
adb version
```

Если появилась информация о версии Android Debug Bridge, настройка выполнена.
На Windows для некоторых моделей телефонов может дополнительно потребоваться USB-драйвер производителя. На Mac отдельный USB-драйвер обычно не требуется.

## 6. Установка Appium
На Mac откройте системное приложение `Терминал`.
На Windows откройте приложение `Командная строка`.

Установите Appium:
```bash
npm install --global appium@3.5.2
```

Установите Android-драйвер Appium:
```bash
appium driver install uiautomator2@8.1.0
```

Проверьте установку:
```bash
appium driver doctor uiautomator2
```

Если в результате написано:
```text
0 required fixes needed
```

обязательные компоненты установлены.
Эти действия выполняются только один раз. После установки Appium полностью перезапустите IntelliJ IDEA.

## 7. Загрузка проекта
1. Откройте IntelliJ IDEA.
2. На стартовом экране нажмите `Get from VCS` или `Clone Repository`.
3. Вставьте адрес:
```text
https://github.com/deno-fo/FitnessOnlineAutoQA.git
```
4. Нажмите `Clone`.
5. Если IDEA попросит войти в GitHub, войдите под аккаунтом, которому выдали доступ.
6. Разрешите IntelliJ IDEA доступ к GitHub.
7. Откройте загруженный проект.
8. Дождитесь завершения загрузки Maven-зависимостей.

При первой загрузке это может занять несколько минут.

## 8. Где вводить команды проекта
Команды запуска тестов нужно вводить в терминале внутри IntelliJ IDEA.

Чтобы его открыть:
1. В верхнем меню IDEA нажмите `View`.
2. Выберите `Tool Windows`.
3. Нажмите `Terminal`.

Вкладка `Terminal` также может находиться в нижней части окна IDEA.
Перед вводом команды посмотрите на строку слева от курсора. В ней должно присутствовать название проекта:
```text
FitnessOnlineAutoQA
```

Пример:
```text
admin@MacBook FitnessOnlineAutoQA %
```

Если названия проекта нет, команда введена не в папке проекта. Закройте терминал и откройте его заново через IDEA.

## 9. Обновление проекта
Перед запуском тестов получите последнюю версию проекта:
1. В верхнем меню IDEA откройте `Git`.
2. Нажмите `Pull`.
3. Дождитесь завершения обновления.

Если IDEA сообщает, что проект уже обновлён, ничего делать не нужно.

## 10. Подготовка телефона
К компьютеру можно одновременно подключить один или несколько Android-телефонов.

На каждом телефоне необходимо:
1. Включить режим разработчика.
2. Включить `Отладку по USB`.
3. Подключить к компьютеру кабелем.
4. Разблокировать экран.
5. Подтвердить разрешение на USB-отладку.
6. Установить приложение FitnessOnline.
7. Переключить приложение FitnessOnline на английский язык (временная необходимость).

> [!NOTE]
> Для устройств с MIUI или HyperOS одной обычной USB-отладки недостаточно.
>
> В меню разработчика необходимо включить:
> - `USB debugging`;
> - `Install via USB`;
> - `USB debugging (Security settings)`.

В терминале IDEA выполните:
```bash
adb devices
```

Подключённые телефоны должны появиться со статусом `device`, например:
```text
List of devices attached
AANBPJMBZ5IRU4JR	device
RFCY60M15XJ	device
```

Фреймворк автоматически получает UDID и название каждого подключённого устройства через ADB, т.о. копировать номера устройств и вручную добавлять их в настройки проекта не требуется.
Если вместо `device` написано `unauthorized`, разблокируйте телефон и подтвердите разрешение на отладку.

## 11. Запуск Appium
В терминале IDEA выполните:
```bash
appium
```

После запуска не закрывайте эту вкладку. Appium должен работать всё время, пока выполняются тесты.
Для запуска тестов откройте вторую вкладку терминала кнопкой `+`.

Для параллельного запуска нескольких Android-устройств достаточно одного сервера Appium. Запускать отдельный сервер для каждого телефона не требуется.

## 12. Запуск всех Android-тестов
На Mac во второй вкладке терминала IDEA выполните:
```bash
./mvnw test -Pandroid
```

На Windows выполните:
```text
mvnw.cmd test -Pandroid
```

После запуска фреймворк автоматически найдёт все подключённые Android-устройства.
Каждый Android-тест будет запущен на каждом обнаруженном устройстве. Запуски на разных устройствах выполняются параллельно.

Во время выполнения:
- не отключайте кабель;
- не блокируйте телефон;
- не закрывайте Appium;
- не нажимайте ничего в приложении вручную.

Перед каждым тестом данные приложения очищаются автоматически.

## 13. Запуск тестов через IntelliJ IDEA
Каждый тест можно запустить без ввода Maven-команды.
Перед запуском должны быть подключены телефоны и запущен Appium.

1. В левой части IDEA откройте:
```text
src → test → java → tests → android
```

2. Найдите нужный тест. Названия Android-тестов начинаются со слова `Android`, например:
```text
AndroidGuestAccountCreationTest
```
3. Откройте файл двойным щелчком.
4. Нажмите зелёный треугольник рядом с названием класса, чтобы запустить все тесты из этого файла.
5. Либо нажмите зелёный треугольник рядом с названием отдельного теста.
6. Выберите `Run`.
При запуске теста или тестового класса через зелёный треугольник IDEA фреймворк автоматически определит все подключённые Android-устройства.

Файлы `BaseAndroidTest` и `BaseIosTest` запускать не нужно. Это не самостоятельные тесты. В них находятся общие настройки.

## 14. Запуск одного теста командой
Этот способ нужен только в том случае, если вам дали точное название теста.

Например, для запуска `AndroidGuestAccountCreationTest` на Mac:
```bash
./mvnw test -Pandroid -Dtest=AndroidGuestAccountCreationTest
```

На Windows:
```text
mvnw.cmd test -Pandroid -Dtest=AndroidGuestAccountCreationTest
```

Команда вводится во второй вкладке терминала IDEA.

## 15. Запуск только на выбранном устройстве
По умолчанию тест запускается на всех подключённых Android-устройствах.

Чтобы выполнить тест только на одном устройстве, передайте его UDID:

Пример на Mac:
```bash
./mvnw test -Pandroid \
  -Dtest=AndroidGuestAccountCreationTest \
  -Dandroid.udid=R58M123456A
```
где AndroidGuestAccountCreationTest - название конкретного теста, R58M123456A - UDID устройства.

Пример на Windows:
```bash
mvnw.cmd test -Pandroid -Dtest=AndroidGuestAccountCreationTest -Dandroid.udid=R58M123456A
```

UDID можно посмотреть командой:
```bash
adb devices
```

## 16. Результат запуска
Результат появится в том же терминале, в котором была запущена команда.
Успешный запуск выглядит примерно так:
```text
POCO X7 Pro [AANBPJMBZ5IRU4JR] | PASS: 1 | FAIL: 0 | SKIP: 0 | TOTAL: 1
```
Если `FAIL` больше нуля, один или несколько тестов завершились с ошибкой.

При запуске на нескольких устройствах один тест отображается отдельно для каждого телефона. В названии запуска указывается имя соответствующего устройства.
Ошибка на одном устройстве не означает, что этот же тест завершился с ошибкой на остальных устройствах.

Некоторые тесты требуют поддержки Google Health. Фреймворк проверяет её автоматически.
Если Google Health недоступен, соответствующие тесты будут отмечены как:
```text
Skipped
```
Это не ошибка. Ничего дополнительно настраивать не требуется.

## 17. Частые проблемы

### Команда `./mvnw` не найдена
Команда введена не в папке проекта. Откройте терминал через IntelliJ IDEA и убедитесь, что в его строке присутствует `FitnessOnlineAutoQA`.

### Команда `appium` не найдена
Appium не установлен или IDEA не была перезапущена после установки.
Установите Appium в системном Терминале на Mac или в Командной строке Windows:
```bash
npm install --global appium@3.5.2
```
После этого полностью перезапустите IDEA.

### Команда `npm` не найдена
Node.js не установлен. Установите Node.js 24 и перезапустите Терминал или Командную строку.

### Команда `adb` не найдена
Не установлены Android SDK Platform-Tools или неправильно настроена переменная `ANDROID_HOME`. Повторите настройку Android SDK для своей операционной системы.

### Телефон имеет статус `unauthorized`
Разблокируйте телефон и подтвердите разрешение на USB-отладку.

Если запрос не появился:
1. Отключите кабель.
2. На телефоне отзовите разрешения USB-отладки.
3. Подключите кабель снова.
4. Подтвердите новое разрешение.

### Телефон не появился после `adb devices`
Проверьте:
- включена ли отладка по USB;
- разблокирован ли телефон;
- подтверждено ли разрешение;
- исправен ли кабель;
- выбран ли режим передачи данных;
- не требуется ли USB-драйвер производителя на Windows.

### Один из подключённых телефонов не участвует в запуске
Выполните:
```text
adb devices
```
Убедитесь, что каждое устройство имеет статус device.
Устройства со статусом unauthorized, offline или без включённой USB-отладки не смогут участвовать в запуске.

### FitnessOnline не установлено
Установите приложение FitnessOnline на телефон и повторите запуск.

### Appium уже запущен
Не запускайте второй сервер. Используйте уже открытую вкладку Appium.
Не запускайте отдельный сервер Appium для каждого устройства. Один сервер обслуживает все параллельные Android-сессии.

### Первый запуск выполняется долго
При первом запуске проект автоматически скачивает Maven и Java-зависимости. Для этого требуется интернет. Последующие запуски будут быстрее.
