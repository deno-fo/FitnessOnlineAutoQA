# FitnessOnlineAutoQA
Appium-автотесты мобильного приложения FitnessOnline для реальных Android- и iOS-устройств.

Проект демонстрирует полный цикл mobile QA automation: от настройки реального
устройства и выдачи системных разрешений до проверки бизнес-сценария и очистки
тестовых данных после выполнения.

## Что покрыто
- создание гостевого аккаунта с разными вариантами разрешений Health Connect;
- регистрация нового пользователя и авторизация существующего;
- выбор готовой программы тренировок;
- создание и прохождение собственной тренировки;
- редактирование и удаление тренировочного дня;
- создание и удаление публикации в Ленте.

## Матрица покрытия

| Сценарий | Android | iOS |
| --- | :---: | :---: |
| Регистрация и авторизация пользователя | ✓ | ✓ |
| Гостевой аккаунт и системные разрешения | ✓ | ✓ |
| Выбор готовой программы | ✓ | ✓ |
| Создание и прохождение собственной тренировки | ✓ | ✓ |
| Редактирование и удаление тренировочного дня | ✓ | ✓ |
| Создание и удаление публикации | ✓ | ✓ |
| Отдельный сценарий регистрации | ✓ | ✓ |

На iOS регистрация нового пользователя проверяется в начале сценария создания
и прохождения собственной тренировки, а также отдельным тестом регистрации.

> [!NOTE]
> Отдельные варианты iOS-регистрации с разными разрешениями пока не добавлены из-за особенностей сброса системных разрешений Apple Health.
> Текущие iOS-тесты рассчитаны на предоставление всех запрашиваемых разрешений Apple Health.

## Инструкции по запуску
- [Запуск Android-автотестов](README_ANDROID.md)
- [Запуск iOS-автотестов](README_IOS.md)

Проверки логики выбора поста и исключения iOS-устройства после неудачной очистки
можно запустить без телефонов и сервера Appium:

```bash
./mvnw test -Dskip.mobile.tests=false \
  -Dtest=FeedPostLocatorTest,DeviceQuarantineTest,CleanupRecoveryTest,PasswordManagerPromptLocatorTest
```

Эти проверки не заменяют мобильный прогон: Android-локаторы проверяются на тестовом
XML-дереве, а исключение устройства — через JUnit без создания Appium-сессии.

Те же быстрые проверки запускаются автоматически в GitHub Actions для каждого
push и pull request. Workflow не требует телефона или Appium-сервера; реальные
мобильные прогоны запускаются командами из платформенных инструкций.

## Архитектура и технические особенности
- **Кроссплатформенная автоматизация:** тесты запускаются на реальных Android- и iOS-устройствах.
- **Технологический стек:** Java 17, JUnit 5, Maven и Appium 3.
- **Драйверы автоматизации:** UiAutomator2 для Android и XCUITest для iOS.
- **Разделение платформенной логики:** для Android и iOS используются отдельные Page Object, компоненты и Flow-классы.
- **Переиспользуемые сценарии:** регистрация, авторизация, первичная настройка приложения, создание тренировок, выполнение упражнений и удаление тестовых данных вынесены в отдельные Flow-классы.
- **Автоматическое определение устройств:** фреймворк самостоятельно находит все подключённые Android-устройства и iPhone. Имена и UDID вручную указывать не нужно.
- **Параллельный запуск:** при подключении нескольких устройств выбранной платформы каждый тест запускается на всех них одновременно.
- **Изоляция устройств:** на каждом устройстве тесты выполняются по очереди, а разные устройства работают параллельно.
- **Отдельные Maven-профили:**
  - `-Pandroid` для Android;
  - `-Pios` для iOS.
- **Управление состоянием приложения:** тесты учитывают системные разрешения, обучающие экраны, подсказки и различия между первым и повторным запуском.
- **Автоматическая очистка данных:** тестовые аккаунты удаляются после завершения сценариев, а на Android перед каждым тестом очищаются данные приложения.
- **Удобное расширение:** новые тесты можно создавать на основе готовых Flow-классов и платформенных настроек.

## Что показывает проект

- умение строить Page Object и Flow-слой для двух мобильных платформ;
- работу с нестабильными нативными окнами: разрешениями, onboarding, tooltip и системным менеджером паролей;
- изоляцию тестов на нескольких реальных устройствах и параллельный запуск;
- восстановление состояния после падения сценария и обязательное удаление созданного аккаунта;
- отдельные быстрые unit-проверки для логики локаторов и очистки, не требующие запуска телефона.
